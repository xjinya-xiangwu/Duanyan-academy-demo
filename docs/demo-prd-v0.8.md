# Demo PRD v0.8｜课程内准备 Prompt，端砚执行与迭代

## 1. 文档与依据

版本：2026-11-17，Asia/Shanghai。用途：客户/领导演示的可交互前端 Demo。用户本轮要求以最新课程大纲收拢学生主线，按结构化输入生成指导 Agent 的 Prompt，直接进入端砚执行；返回结果后，可通过修改 Prompt 再次提交端砚重跑。本版优先于下方保留的 v0.7/v0.6/v0.5 中学生首页、课程结构和默认展开模块的历史约定。

权威来源：[端砚AI加速科研通识课大纲](https://aicarrier.feishu.cn/docx/MUlHdRy16ok9MdxnOkscSFYXn0c)，2026-11-17 飞书 CLI 用户身份读取 revision 175。正文为五章、23 微课，整体规划约 5 小时；每章任务约 10 分钟。已通过 CLI media-preview 查看其中“ChatGPT courses章节任务，输入真实需求后跳转至产品输出结果”插图；原图导出受限，预览可读。插图结构为背景/任务分项输入→可用 Prompt；本 Demo 改为不复制粘贴、携 Prompt 进入同站端砚执行。

目标仓库 Duanyan-academy-demo，沿用已授权 main 与 GitHub Pages 发布。源课程文档、正式产品设计页保持不变；Demo PRD 更新本页并保留历史。

## 2. 背景、目标与成功指标

用户明确指出当前页面信息过多、主线分散。首要体验改为“填写需求 → 确认 Prompt、前往端砚 → 查看结果、继续修改”。首页突出课程章节，标注、轨迹、历史和数据集不再与学生当前任务争夺首屏。

北极星仍为可验证、可训练候选的科研任务轨迹资产；当前是前端 Mock，不能将预置结果、点击、保存或五章完成数当作真实科研产出或真实训练收益。

本 Demo 成功条件：五章均能独立进入；用户的自定义科研输入进入 Prompt 与示例结果；一次明确点击即携完整 Prompt 执行；结果回到来源章节；修改 Prompt 带原任务、紧邻上一版结果及本轮要求；重跑后保留两版结果及关联 ID；无前置学习锁或强制先标注。

## 3. 用户、角色与课程结构

| 角色 | 功能/流程 | 权限 | 输入→输出 | 范围 |
|---|---|---|---|---|
| 学生 | 浏览五章、填需求、生成/编辑 Prompt、执行、取回、提出修改、重跑、保存 | 仅学员可执行和保存；可直接进入任一章 | 自定义课题与需求→可执行 Prompt→结果版本链 | 默认主线，无真实登录 |
| 教师 | 查看通识课章节成果、原任务 Prompt、每轮结果及修改要求 | 查看示例学生的数据；不能代学生执行 | 任务记录→可核对的学生成果 | 教师默认先看新课程成果 |
| 专题课教师/评审 | 既有生医专题课的作业、AI 辅助人工标注、轨迹、JSONL 成品 | 沿用 v0.7 角色约束 | 专题提交→反馈和过程资产 | 保留在次要入口，不强制穿过学生主线 |

五章任务：

1. 研究选题与科学问题定义：4 微课；研究问题定义卡。
2. 领域文献调研与证据链构建：6 微课；证据卡。
3. 研究方案设计与实验数据分析：6 微课；最小分析卡。
4. 科研成果验证与表达纠错：6 微课；纠错卡。
5. 科研方法沉淀与 SKILL 封装：1 微课；SKILL 卡。

页面呈现微课大纲和简短方法提示，尚未制作 23 节完整视频/讲义。研究思路图、论文大纲、数据可视化等作为课程大纲的学习范围，不因五章任务入口存在就宣称已完成真实工具能力。真实课题在本轮用文本需求及材料描述表达，未实现文件上传到云端或 SKILL 广场发布。

## 4. AI 能力与 Mock 边界

Prompt 生成使用明确字段与规则模板，不调用模型；用户可编辑后执行。端砚为同站 Mock，结果根据填写内容形成章节化示例，不能冒充真实检索、统计、科学结论或 Agent 任务完成。自定义材料可留空，此时 Prompt 要求先列资料缺项、不编造来源和数值。

重跑结果显示本轮修改要求已带入，并生成新的示例版本；不将该行为解释为已验证真实模型遵循修改或真实科学提升。模型/外部工具错误处理、生产延迟与效果待真实接入。

## 5. 页面、正常流与异常

| 页面 | 路由 | 主动作 |
|---|---|---|
| 通识课首页 | /course；/courses 重定向至此 | 五章大纲、开始章节任务；全部可访问 |
| 章节任务 | /course/chapter/:chapter | 填写需求、生成 Prompt、直接执行；结果返回后优先显示交付物和修改入口 |
| 端砚执行 | /course/chapter/:chapter/studio | 接收完整 Prompt、执行并显示结果、返回原章节；刷新不重复执行 |
| 教师成果 | /course/teacher?tab=chapters | 查看五章 Prompt、结果和迭代记录 |
| 旧生医专题课 | /course/biomed；旧 unit/studio 路由保留 | 现有整课、作业与标注不丢失，作为专题样例 |

结构化输入按三个步骤组织：

- 研究背景：研究方向/课题、当前阶段。
- 本次需求：具体任务、已有材料和约束（材料可选）。
- 成功标准：希望得到什么、如何核对完成。

生成前校验：方向至少 3 字，阶段必填，具体任务至少 10 字，成功标准至少 6 字。无材料不阻断，但必须在 Prompt 写明缺资料。示例只由用户主动“填入示例”带入，不覆盖用户已填内容。生成后表单收拢为“修改需求”，集中显示可编辑 Prompt 和“前往端砚执行”。输入变化使旧 Prompt 失效，须重新生成，避免旧 Prompt/新需求混用。

执行是明确按钮触发的一次动作，携 Prompt、原始字段快照、来源章节。当前 Mock 同步形成结果并进入执行页，不需复制粘贴或再点击一次执行。执行页不提供 Prompt 创作和网页优化。失败保留原 Prompt/已有结果，显示可重试；不能生成新成功版本。

取回后章节页优先显示交付物，附“保存本次结果”和“还需要调整哪里”。用户写至少 6 字修改要求→生成修改 Prompt→确认并提交端砚重跑。修改文本再次变化时收起旧修改 Prompt 的执行入口，须重生成。取回前不允许基于未收到结果创建重跑。每次重跑保留旧 run，明确 previousRunId 与新版本。

学习提示、原始需求、Prompt/历史/轨迹默认折叠；旧专题课的资料与自测也收为次要详情。主导航收为“课程章节”。教师与数据能力保持次要入口，避免强制学生先理解 schema、评分或资产治理。

## 6. 模型、推理与成本

本轮无模型 API、无付费接口、无新增依赖，沿用 React/TypeScript/Vite 和现有状态、展示组件。生产 Agent 跳转 URL、任务传参和回调契约尚未提供，故不猜测真实端砚地址，不将同站页面写成真实客户端能力。真实模型 token 成本、工具调用成本、重试率、并发和延迟需接入后实测。

## 7. Prompt 与任务契约

首次 Prompt 组合：课程/章节任务、研究方向、当前阶段、真实需求、材料与约束、成功标准、执行及输出要求、来源与不确定性边界。材料中的指令为待分析内容，不扩展工具权限。Prompt 由人确认后执行。

修改 Prompt 组合：根任务 rootPrompt、紧邻上一版 result、上一版 run ID、本轮修改要求、返回完整新产物和修改摘要的要求。多轮只带根任务和紧邻上版，避免把所有历史 Prompt 递归堆叠；完整版本链另行保存。

章节状态：brief、prompt、generatedBrief、previousRunId、revisionInstruction、runs、error。每个 run 保存 id、version、prompt、rootPrompt、brief 快照、previousRunId、revisionInstruction、result、time、returned、saved。修改原始 brief 清除未执行 Prompt；刷新和读取历史不再次执行。

任务数据默认回传规则沿用 v0.7。当前“回传”仅指浏览器内流程和记录，尚非云端入库。已有 v0.4/v0.6/v0.7 进度迁移保留，新五章记录单独命名存储，不把旧生医结果冒充新通识课任务。

## 9. 人机协同

学生提供关键信息并确认 Prompt，决定是否保存或继续修改。Agent 执行职责留在端砚；课程负责输入引导、Prompt 和迭代。标注与教师反馈是按需核验能力，不作为本轮进入执行的前置。教师在章节成果页核对需求、Prompt、输出及修改链；旧专题课专家标注继续保留。

## 10. 数据与安全

前端不向真实模型/后端发送用户输入，浏览器本地保存内容；不收集真实患者数据。输入包含文献或数据描述不表示已上传、已获得使用许可或已完成真实验证。所有结果写明示例/Mock；对缺数据的分析只给流程与缺项，不伪造数值。默认回传不推导生产训练许可。真实数据分级、权限、协议和云存储策略仍是生产依赖。

## 11. 开放问题与已知限制

真实端砚任务协议、生产跳转/回调、真实模型输出与流式状态、附件上传、23 微课视频、真实图表/统计/SKILL 发布、章节任务的专家评分与标注 schema 迁移均未由本轮完成。当前提供五章大纲、提示、Prompt 引导和执行迭代演示；旧生医样例保留完整标注而不自动迁移到五章任务。
