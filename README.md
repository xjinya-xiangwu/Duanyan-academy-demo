## 怎么走一遍

顶栏切换「学生 / 老师 / 评审」。学生从课表进入。老师从「我的课」进入。看板只在老师／评审导航里，学生课首页没有回流总数。

1. 老师：选用生医 6 步模板，生成邀请码或导入名单「林可」，发布。
2. 发布前可以勾上「卸下强制实训步骤」。这时发布会被阻断。
3. 学生：从课表进入。无效码，或不在名单的姓名，会停在课入口。有效码是老师页上的 `生医6-DEMO`。
4. 课首页是 6 步。步骤①和⑤可以标记已读，不计回流。
5. 步骤②创建课题，打开端砚（演示）。只打开、空点优化、或模拟失败，都不计数。生成问题界定，优化一次，再回传。
6. 步骤③、④同样回传。④会挂一张同一课题的演示图。三步齐了才是待抽检。课页勾选「我已完成」或站外交差说明都不计数。
7. 老师在班级进度看到「待抽检」，抽检页能看到带入、执行、优化、回传。AI 辅助评估只给建议。可以先打回步骤②，学生重新生成并回传后再次待抽检，再点通过。
8. 学生课首页显示已通过。这不是证书。评审在看板看到回流口径、四项分项，以及「布置 → 作答轨迹 → 抽检」。

按上面这条路径，并且步骤②只成功优化 1 次、三步各成功回传 1 次、评估成功 1 次时，看板是：

| 分项 | 数字 |
|-|-|
| 实训步骤执行／产物回传 | 1 |
| 提交前 Agent 优化 | 1 |
| 老师 AI 辅助评估 | 1 |
| 同一课题后续实训步骤再回传 | 2 |
| 合计 | 5 |

补做后的再次回传不增加，已计入的数字也不扣。同一步第二次成功优化可以再 +1，第三次不再加。同一次提交重复评估不加。这些规则在 `src/domain/logic.test.ts`。

## 哪些是 Mock

- 课包、prompt、产物、优化结果、评估建议、轨迹和看板数字都是写死的演示内容。
- 生成、优化、评估会等大约半秒，然后显示固定文案。等待不调用模型。
- 步骤④的图是页面里的静态示意，不是生图接口的输出。
- `step_id`、`event_kind`、`counted`、`topic_ref` 只是演示字段。

## 本 Demo 不覆盖

- 真实端砚客户端、真实后端、登录和轨迹 API。
- 成绩册、0–100 分、等第、证书、完课率 KPI、SIS、公开报名、创作台、讨论区、通知中心。
- 步骤⑤的互评交互。这一步只展示，不计成功。
- 老师路径 T10 的截止提醒。
- 把本 Demo 写成正式产品 P0 或完整教务 LMS。
