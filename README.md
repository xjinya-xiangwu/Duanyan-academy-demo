# 课＋轻量 LMS＋端砚（前端预览）

这是 Demo PRD v0.4 的可点击前端。打开是一门可以学完的生医课。页面数据都是 **演示／Mock**。这里不是生产系统，没有真实端砚跳转，也没有真实轨迹入库。

预定的 GitHub Pages 地址只是预览入口，不是本 PR 的交付，也不是生产上线：

https://xjinya-xiangwu.github.io/Duanyan-academy-demo/

本 PR 不合并 `main`，也不改 Pages 设置。`.github/workflows/pages.yml` 仍在 pull request 上运行 `npm test` 和 `npm run build`，只在 `main` 上传并发布 Pages。

## 本地预览

```bash
npm install
npm test
npm run dev
```

浏览器打开：

http://localhost:5173/Duanyan-academy-demo/

站点基路径是 `/Duanyan-academy-demo/`。构建后再看静态结果：

```bash
npm run build
npm run preview
```

预览地址是 http://localhost:4173/Duanyan-academy-demo/ 。刷新深层路由时，`404.html` 会把请求交回这个单页应用。

学员路径的浏览器走查：

```bash
npx playwright install chromium
npm run test:e2e
```

截图目录默认是仓库里的 `e2e/screenshots`。要改目录，设置环境变量 `E2E_SCREENSHOT_DIR`。`npm test` 只跑状态机，不安装浏览器。GitHub Actions 因此不跑 `test:e2e`。

进度保存在当前浏览器的 `localStorage`。页脚的「重置本课进度」回到起点。身份切换在页脚。

## 附录 A 怎么走

默认是学员，首屏是课表。示例课已经可以进入。

1. 课表进入「PD-1 与 PD-L1：机制示意与文献综述」。另开「用邀请码进入」：`无效码` 会被拒绝，名单外的姓名也会被拒绝。有效码是 `生医6-DEMO`。
2. 大纲顺序是教学课时、测验 Q1、作业 ②③④、可选互评。读完教学课时。这一步不计完成，作业也不会变成待反馈。
3. 测验 Q1 从「在端砚中完成（演示）」进入同站薄页。可以先优化再回传。结果出现在这一测验上。作业 ②③④ 仍不是待反馈。
4. 作业 ② 先打开课题，再回传问题界定。作业 ③ 回传论文段落。作业 ④ 回传同一课题的示意图。三份齐了，作业位变成待老师反馈。课页勾选和站外文稿都不计。
5. 页脚换成老师，在作业 ② 的提交上看到带入、执行、优化、回传。可以点 AI 辅助评估，再点请修改。
6. 换回学员，这一份解锁。重新生成并回传后再次待反馈。老师再点通过。作业位显示已通过。这不是证书。
7. 回流数只在这门课的教师视图末尾。教学已读不加。测验的回流也不代替三份作业。

按上面这条路径，测验 Q1 优化 1 次并回传，作业 ② 优化 1 次并回传，作业 ③④ 各回传 1 次，再对作业 ② 评估 1 次，教师视图是：

| 分项 | 数字 |
|-|-|
| 实训执行／产物回传 | 2 |
| 提交前 Agent 优化 | 2 |
| 老师 AI 辅助评估 | 1 |
| 同一课题后续作业步骤再回传 | 2 |
| 合计 | 7 |

请修改后的再次回传不增加，已计入的数字也不扣。同一单元第三次优化、重复回传、重复评估也不增加。

老师若要看布置：在教师视图选用生医模板，生成邀请码或导入名单后发布。勾选去掉作业 ②③④ 再发布，会被阻断。这不改变正在上的这门课。

## 哪些是 Mock

- 讲义、测验、作业、产物、优化、评估建议、轨迹和回流数字都是写死的。
- 生成、优化、评估会等很短的时间，然后显示固定文案。等待不调用模型。
- 作业 ④ 的图是页面里的示意图，不是生图接口的输出。
- `unit_id`、`event_kind`、`counted`、`topic_ref` 只是占位。

## 本 Demo 不覆盖

- 真实跳转到端砚，真实后端，真实轨迹入库。
- 成绩册、分数、证书、讨论区、公开报名、创作台。
- 可选互评只展示，不做互评操作。
- 截止提醒。

Pages 仍要等本 PR 合并到 `main`，并且仓库的 Pages 来源是 GitHub Actions，才会更新预览。合并本身不在本 PR 里完成。
