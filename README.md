## 附录 A 点击路径

从重置后的学生视图开始。顶栏可以在「学生 / 老师 / 看板」之间切换。顶栏的「回流 N」会跟着计数变化，完整口径在看板。

1. 打开 `/course`。确认教学步骤旁有「不计成功」，长程阶段条有 3 段，阶段 2 和阶段 3 为锁定。课题名是「示例课题：PD-1／PD-L1 机制示意与文献综述」。
2. 进入阶段 1 的课堂任务。展开资源清单和 prompt 摘要，点「打开端砚（演示）」。
3. 在端砚执行页确认「已带入」是阶段 1 的内容。先点「用 Agent 优化 deliverable（演示）」，应提示先生成产物，回流数不变。再点「回传课内作业位」，应提示未达回传条件，回流数不变。然后点「生成本阶段产物」，约 1.5 秒后出现固定 Mock 短文。再点优化：出现优化前 / 优化后的可见差异，优化分项 +1，状态变为「已优化未回传」，作业位仍是未回传。然后再点回传：回传分项 +1，状态变为待抽检。
4. 打开课内作业位。阶段 1 有产物，状态为已入库／待抽检。勾选「我已完成」：出现「课页交差不计成功」，产物和回流数不变。再点阶段 2 的「进入该阶段」：提示先完成本阶段抽检通过，阶段 2 仍锁定。
5. 切到老师视图。时间线里能看到优化事件。点「AI 辅助评估（演示）」：约 1.5 秒后出现没有评分的建议，评估分项 +1，状态仍是待抽检。再点「通过」。回到学生课程页，阶段 2 变为未开始，课题名不变。
6. 学生进入阶段 2。任务页和执行页的带入稿换成阶段 2（含 `ref-list.mock.csv` 和两条 skills 草案）。生成本阶段产物并回传。回传分项再 +1。优化可以再走一次，不强制。
7. 打开看板。看到公式、计入、不计、去重，以及总数和三项拆分。数字旁有「演示／Mock」。
8. 失败分支可以在对应步骤插入：无产物时点优化；未回传时在抽检页点评估；页脚武装「模拟下一次生成失败」后点生成，看到「演示：失败」，再点一次生成可以成功；没有轨迹时在抽检页点通过；锁定阶段点进入。这些操作都不增加回流数。补做不减少已有数字；同一阶段再次回传、第三次优化、重复评估也不增加。

只走上面的阶段 1 优化 1 次、回传 1 次、评估 1 次，再加上阶段 2 回传 1 次，并且没有做第二次优化时，看板应为：

| 分项 | 数字 |
|-|-|
| 提交前 Agent 优化 | 1 |
| 阶段执行／产物回传 | 2 |
| 老师 AI 辅助评估 | 1 |
| 合计 | 4 |

阶段 1 若再优化到第 2 版，优化变为 2，合计变为 5。第 3 次优化不再增加。

走完 3 个阶段的老师通过之后，课程页出现「长程课题已走完引导路径（演示）」。这不是证明文书，也不进入回流数。

## 哪些是 Mock

- 课包、prompt、附件、skills、产物、优化结果、评估建议、轨迹、看板数字，全部是写死的演示内容。
- 生成、优化、评估会等待约 1.5 秒，然后显示固定文案。等待不调用模型。
- 机制图是页面里的静态占位图，不是生图接口的输出。
- 优化第 1 版和第 2 版的差异是预先写好的，用来对照，不是现场改稿。
- 演示字段 `stage_id`、`event_kind`、`counted`、`topic_ref` 只是占位。生产事件字典【待补充】。

## 本 Demo 不覆盖

- 真实跳转到端砚客户端或生产环境。「打开端砚（演示）」只切换本站页面。
- 真实后端、登录、鉴权、名单和轨迹 API。
- 生产轨迹入库。看板数字不是云端回流。
- 成绩册、0–100 评分、证书、完课徽标、公众号、Word／LaTeX 发表包、以 Notebook 为主界面、LTI。
- 多课题、跨学期的科研管理系统。这里只有 1 条虚构生医课题和 3 个引导阶段。

## GitHub Pages

仓库里的 `.github/workflows/pages.yml` 会在 pull request 上运行测试和构建，只在 `main` 分支把 `dist` 发布到 Pages。构建使用站点基路径 `/Duanyan-academy-demo/`。

若预览地址还打不开，仓库所有者还需要做一次设置：

1. 把本 pull request 合并到 `main`。
2. 打开仓库 Settings → Pages → Build and deployment。
3. Source 选择 GitHub Actions。
4. 若合并当时的发布工作流没有成功，在 Actions 里重跑 “Preview GitHub Pages”。

这一步不能由 pull request 本身完成。完成之后的页面仍然是预览，不是生产发布。
